# ELEMON ― ブラウザ・モンスター育成RPG 完全設計書

> 本書は実装の唯一の仕様書である。固有IPは一切使用しないオリジナル設計。
> 単一 `index.html`（HTML/CSS/JSのみ・ビルド不要・ダブルクリック起動）で全要件を満たす。

---

## 1. ゲームコンセプト定義

**目的**: 「捕獲→育成→編成→攻略」の中毒性ループを、短時間で完結する1本道RPGとして提供する。

**仕様**
- ジャンル: 2Dタイル探索 + ターン制コマンドバトル + クリーチャー収集。
- コア体験: 野生エレモンを弱らせて捕獲し、6体パーティを編成、属性相性を読んでトレーナーを攻略。
- 勝利条件: 最終エリア「天空塔」のボス「監督者ヴァロン」を撃破しエンディング到達。
- 失敗条件: パーティ全滅 → 最後にセーブした拠点で復帰（所持金10%ロスト、進行は保持＝詰みなし）。
- 1プレイ時間: 初回クリア 35〜50分。スピードラン 18分目安。
- リプレイ性: 図鑑コンプリート（全18種）、3スターターの相性違い周回、撃破タイム記録。
- 差別化: 全自動アセット生成（Canvas描画＋WebAudio合成）でゼロ外部依存。即起動・即プレイ。

**受け入れ基準**: 起動から60秒以内に最初の戦闘へ到達できる。全滅しても必ず再開でき進行ロストがない。

---

## 2. 対象環境・技術制約

**仕様**
- 技術: HTML5 / CSS3 / Vanilla JS（ES2019）。外部CDN・画像・音声ファイル・モジュール読込なし。
- 対応: Chrome/Edge/Firefox/Safari 最新2バージョン。`file://` ダブルクリック起動を保証。
- 画面: 論理解像度 960×640（3:2）。CSSで画面にフィット（`object-fit`相当のスケール）、ピクセルパーフェクト。
- 入力: キーボード主（矢印/WASD=移動、Z/Enter=決定、X/Esc=キャンセル、M=メニュー）。マウス/タッチでUIボタン操作も可（仮想ボタン表示）。

**実装ルール**: ESモジュール禁止（file://のCORS回避）。全コード1ファイル内のIIFE名前空間で分離。`requestAnimationFrame`固定タイムステップ。

**受け入れ基準**: ローカルでダブルクリックして警告なく起動。1280×800以上でレイアウト崩れなし。

## 3. コアループ設計

```
拠点(回復/購入/セーブ) → フィールド探索 → 野生戦闘 → 捕獲/経験値 →
レベルアップ/編成 → トレーナー戦(関門) → バッジ獲得 → 次エリア解放 → …
→ 最終ボス → エンディング → 周回(任意)
```

**仕様**: 1サイクル平均3〜5分。各エリアは「野生狩り場 → 中ボストレーナー → バッジ → ゲート解放」で1単位。
**接続**: §5ステージ進行が§7成長を駆動し、§8経済が§2拠点機能に接続。
**受け入れ基準**: どのサイクルも中断ポイント（セーブ）が5分以内に存在する。

## 4. ルール・メカニクス設計

**操作**
- フィールド: 4方向グリッド移動。1マス=32px、移動速度=8px/frame（4frameで1マス、約66ms@60fps）。
- 戦闘: コマンド選択（たたかう/エレモン/どうぐ/つかまえる/にげる）。

**当たり判定**
- フィールド: タイル属性配列。`0`=床/`1`=壁/`2`=草(エンカウント)/`3`=NPC/`4`=ゲート/`5`=拠点。
- 草地1歩ごとにエンカウント抽選: `P = 0.10 + 0.01*連続歩数`（上限0.28、戦闘で0リセット）。

**ダメージ計算（決定論＋小乱数）**
```
base = floor( ( (2*Lv/5 + 2) * Power * Atk / Def ) / 50 ) + 2
dmg  = floor( base * STAB * TypeEff * rand(0.90,1.00) )
STAB = 1.5 (技属性==使用者属性) else 1.0
TypeEff ∈ {0.5, 1.0, 2.0}  (相性表 §6)
命中: acc% 判定（外れ=0ダメージ）。会心: 6.25%で *1.5。
```
**捕獲判定**
```
a = floor( (3*MaxHP - 2*HP) * captureRate * ballMul / (3*MaxHP) )  // 0..255
shake成功確率 b = a/255、4回連続成功で捕獲。HP割合が低いほど成功。
```

**難易度係数**: トレーナーLvはエリア標準+2、ボスは+4。野生はエリア範囲内一様乱数。
**ランダム要素**: ダメージ乱数±10%、命中/会心、エンカウント、捕獲シェイク。シード不要（体感ランダム）。

**受け入れ基準**: 同条件で計算結果が±10%内に収束。0除算・NaN・負ダメージが発生しない（最低1保証）。

## 5. レベル/ステージ設計

**仕様（4エリア＋塔）**
| エリア | 名称 | 推奨Lv | 野生Lv | 関門 | 解放条件 |
|---|---|---|---|---|---|
| A1 | 始まりの草原 | 1-6 | 2-5 | トレーナー×1 | なし |
| A2 | 木霊の森 | 6-12 | 6-10 | 中ボス（バッジ1） | A1関門突破 |
| A3 | 灼熱の渓谷 | 12-18 | 12-16 | 中ボス（バッジ2） | バッジ1 |
| A4 | 凍てつく岬 | 18-24 | 18-22 | 中ボス（バッジ3） | バッジ2 |
| T  | 天空塔 | 25+ | 24-28 | 最終ボス | バッジ3 |

**ギミック**: ゲートタイル(4)はバッジ数で開閉。各エリアに回復拠点(5)とショップNPC、隠しアイテム1個。
**復帰導線**: 全滅時は直近拠点へワープ・全回復。詰み防止: 拠点でレベル上げ無限可、回復薬は所持金0でも野生から復帰可能（最低限の経験値で再戦可）。
**受け入れ基準**: バッジ未取得でゲート通過不可・取得後は必ず通過可。全滅後に必ず操作可能状態へ戻る。

## 6. エンティティ設計

**属性（6種）と相性表**（攻→防, 2.0=有利, 0.5=不利, 空=1.0）
- 草→水2.0 / 火0.5
- 火→草2.0 / 水0.5
- 水→火2.0 / 草0.5
- 電→水2.0 / 地0.5
- 地→電2.0(無効化せず) / 草0.5
- 無 → 全1.0（汎用）

**ステータス基本式**: `Stat = floor(Base*Lv/50) + Lv + 5`（HPのみ `+Lv*2+10`）。
**エレモン種族（18種・各属性3〜4体、Base値 HP/ATK/DEF/SPD/captureRate）**: データは§13 JSONに定義。スターター3種（草/火/水）。
**敵AI**: 80%で最大期待ダメージ技、20%でランダム。HP<25%かつ回復技保持時50%で回復。トレーナーは交代AIあり（不利相性で30%交代）。
**生成/消滅**: 野生は草地抽選で1体生成、戦闘終了でGC。トレーナーは固定配置、撃破でフラグ消滅。

**受け入れ基準**: 全18種が図鑑に出現可能。AIが不正技を選ばない。相性が双方向で矛盾しない。

## 7. 成長・進行システム

**仕様**
- 経験値: `EXPgain = floor(enemyBaseExp * enemyLv / 7)`、必要EXP `need(Lv)=floor(Lv^3*0.8)`。
- レベル上限50。レベルアップで全ステ再計算、HP差分回復。
- 技習得: 種族ごとに `learnset`（Lv到達で習得、最大4技、5個目は最古を置換しUI確認）。
- 進化: 指定種は `evolveLv` でフォルム変化（Base+技更新、図鑑別枠）。3種が進化可能。
- アンロック: バッジ取得で上位ボール購入解放・新エリア・新ショップ在庫。

**接続**: §4ダメージ式・§6ステ式と一貫。§8通貨で道具購入が成長を補助。
**受け入れ基準**: Lv50で式が破綻しない。技4超で必ず置換UIが出る。進化後ステが進化前を下回らない。

## 8. 経済・リソース設計

**仕様**
- 通貨「ジェム」。戦闘報酬 `gain = enemyLv*6 + rand(0,10)`、トレーナーは×3。
- 消費: 回復薬(50/120/300) / ボール(通常80・上位200・最上位450) / 解放はバッジ進行。
- 報酬期待値: A1で1戦≒25G、薬1個=50G → 約2戦で1薬。インフレ抑制: ボス報酬は固定上限、売却なし。
- 救済: 所持金<30かつ薬0なら拠点で「支援薬」1個無償配布（1回/全滅毎）。

**受け入れ基準**: 通常プレイで詰み（金欠＋薬0＋勝てない）が発生しない。負債・マイナス残高なし。

## 9. UI/UX仕様

**仕様**
- HUD（フィールド）: 左上=所持金/バッジ、下=操作ヒント。応答<100ms。
- 戦闘UI: 上=敵HPバー＋Lv、下=自HPバー＋EXPバー、コマンド4分割。HPバー減少アニメ300ms。
- メニュー(M): パーティ/どうぐ/ずかん/セーブ/もどる。キーボード・クリック両対応。
- チュートリアル: 初回起動時オーバーレイ4枚（移動/草/戦闘/捕獲）、Skip可、再表示は設定から。
- フィードバック: ダメージ数字ポップ、被弾フラッシュ、捕獲シェイク演出、トースト通知2.5秒。
- アクセシビリティ: 色覚補助（属性に記号併記 草◆火▲水●電✦地■無◇）、テキスト速度3段、画面振動OFF設定、フォーカスリング表示。

**受け入れ基準**: 全操作がキーボードのみで完結。マウスのみでも完結。色なしでも属性判別可。

## 10. コンテンツ仕様

**仕様**
- ストーリー最小構成: 導入（師から最初の相棒）→ 4エリア踏破 → 塔の監督者を止める → 帰還エンド。テキスト各シーン2〜4行。
- ミッション: メイン=バッジ4＋ボス。サブ=図鑑10種/全種、隠しアイテム4個回収。
- ボス: 中ボス3（バッジ）＋最終ボス1（3体PT・Lv28）。
- エンド条件: 最終ボス撃破でエンディング画面（プレイ時間/捕獲数/撃破タイム表示）→ 周回継続可。
- やり込み: 図鑑コンプ、ノーダメ撃破記録、最短クリアタイマー。

**受け入れ基準**: メインクリア導線が一本道で迷子にならない。エンド後もセーブから継続可能。

## 11. オーディオ/演出仕様

**仕様（WebAudio合成、音声ファイル不要）**
- BGM: フィールド/戦闘/ボス/勝利の4種をオシレータでループ生成（矩形波メロディ＋ベース）。音量初期30%。
- SE: 決定/キャンセル/被弾/会心/捕獲成功/回復/レベルアップ。
- 演出: ヒットストップ80ms、被弾時画面シェイク（振幅6px・180ms、設定でOFF）、シーン遷移フェード250ms、戦闘開始ズームワイプ400ms。
- 通知: 右上トースト（取得/習得/進化）2.5秒スライド。

**受け入れ基準**: 初回ユーザー操作後に音が鳴る（autoplay制約遵守）。OFF設定で完全無音。

## 12. アートディレクション

**仕様**
- 2D・Canvas手続き描画。外部画像ゼロ。
- アセット規格: タイル32px、エレモンは48px円形ボディ＋属性色＋目/口のパーツ描画で種別差。
- 色設計: 草#4caf50 火#ff5a3c 水#3aa0ff 電#ffd43b 地#b07a3a 無#9aa0a8。背景はエリア別パレット。
- アニメ: 待機ボビング（sin, 2px/0.6s）、攻撃時0.12sラン、被弾0.1s赤点滅、捕獲縮小回転。
- 視認性: HP緑→黄(50%)→赤(20%)。文字は黒縁取り＋白で全背景可読。最小フォント16px。

**受け入れ基準**: 18種が形/色/記号で識別可能。HP状態が一目で判別可能。

## 14. アーキテクチャ設計

**ファイル構成**: 単一 `index.html`（`<style>` ＋ `<script>` 内 IIFE）。論理モジュール:
- `DB` データ定義（species/moves/areas/trainers/items）
- `Audio` WebAudio合成（BGM/SE）
- `Save` localStorage I/O＋バージョニング
- `Battle` 戦闘状態機械
- `World` フィールド/タイル/移動/エンカウント
- `UI` HUD/メニュー/トースト/チュートリアル
- `Game` シーン管理＋固定タイムステップループ

**状態管理**: 単一 `state` ツリー。シーン=`{ TITLE, FIELD, BATTLE, MENU, DIALOG, END }` の有限状態機械。
**イベント駆動**: 入力→`Input`バッファ→現在シーンの`update(dt)`/`render`へディスパッチ。`emit/on`簡易バス。

**受け入れ基準**: シーン遷移時に前シーンの入力/タイマーが残留しない。例外は`try/catch`で握り再起動可能。

## 15. 保存設計

**仕様**
- キー `elemon.save.v3`、設定 `elemon.settings`。手動セーブ（メニュー）＋拠点接触オートセーブ。
- バージョニング: `ver`不一致時マイグレーション（欠損補完）。読込失敗/JSON破損時は新規データで起動しトースト警告。
- 復旧: パース例外→バックアップキー`elemon.save.bak`を試行→不可なら初期化。

**受け入れ基準**: 破損文字列を入れても起動可能。旧verでも遊べる。セーブ後リロードで完全復元。

## 16. パフォーマンス要件

**仕様**: 目標60fps（最低45）。固定dt=1000/60、最大フレームスキップ5。
- 描画最適化: タイルは可視範囲のみ、静的背景はオフスクリーンCanvasキャッシュ。
- オブジェクトプール: ダメージポップ/パーティクルを再利用（new禁止区間）。
- GC抑制: ループ内オブジェクト生成回避、配列再利用。
- ロード: 初期化<300ms（アセット生成含む）。

**受け入れ基準**: 連続10戦でfps45以上維持、メモリ単調増加なし。

## 17. 品質保証（QA）計画

**テスト観点**
- 機能: 移動/エンカウント/全コマンド/捕獲/レベルアップ/進化/セーブ/全滅復帰/エンド。
- 負荷: 連打（決定キー20連打で多重遷移なし）、長時間放置。
- 回帰: セーブ→各機能→ロードで状態一致。
- UX: チュートリアル離脱、色補助、無音設定。
**バグ優先度**: P0=起動/進行不能・セーブ破壊 / P1=戦闘計算誤り・詰み / P2=演出/表示 / P3=軽微。
**受け入れ基準**: P0/P1ゼロでリリース可。

## 19. リスクと回避策

- スコープ肥大→種族18/エリア4で固定、追加は周回要素のみ。
- バランス崩壊→§4式を単一関数化し数値を定数表に集約、調整1箇所。
- 技術負債→単一ファイルだがモジュールIIFE分離で責務明確化。
- 運用不能→外部依存ゼロ・file://動作保証でホスティング不要。
- セーブ破損→バックアップ＋マイグレーションで常に起動可能。
